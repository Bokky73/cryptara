# Internationalization (i18n) & Localization Guide

Cryptara supports multi-locale user interfaces via typed message catalogs, locale negotiation, and shared Intl formatters.

## Supported Locales

- `en` (English - Default)
- `tr` (Turkish)

## Locale Configuration & Negotiation

Locale resolution is configured in `frontend/src/i18n/config.ts`.
Preference order:
1. `gr-locale` cookie / localStorage explicit user preference.
2. `Accept-Language` HTTP header negotiation.
3. Fallback to `en`.

Timezones are resolved via `gr-time-zone` cookie, defaulting to `UTC` if invalid or missing.

## Adding New Message Keys

1. Add the key and English translation to `frontend/src/i18n/catalogs/en.ts`.
2. Add the corresponding localized text to all other active catalogs (e.g. `frontend/src/i18n/catalogs/tr.ts`).
3. TypeScript compiler enforces exhaustive key parity; missing keys in any catalog fail the build.

## Verifying Catalog Parity

Run the validation script from the `frontend` directory:
```bash
node --import tsx scripts/history-i18n-check.ts
```

## Value Formatting Guidelines

Always use `createFormatters(locale, timeZone)` from `frontend/src/i18n/format.ts`:
- Percentages are represented as decimal fractions (`0.42` formats as `42%`).
- Currency values format according to locale symbol positioning and standard decimals.
- Timestamps format using the resolved user timezone.
